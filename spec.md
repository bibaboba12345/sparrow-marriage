# MedTech Hackathon: Автоматическая платформа маршрутизации пациентов

**Срок разработки:** 3 дня

**Концепция:** Автоматический разбор выписок/анализов пациентов и их маршрутизация на основе Decider LLM (Structured Output) + RAG с клиническими гайдлайнами.

## 1. Архитектура системы

### 1.1 Текстовая схема архитектуры

```
[Пользователь / Врач]
        │
        ▼ (Загрузка PDF / Эпикриза / Анализов)
[Frontend Interface]
        │
        ▼ (HTTP REST API)
[FastAPI Backend]
        │
        ├─► [Parser Module] ──► Извлечение чистого текста из PDF/DOCX/Images
        │
        ├─► [RAG Engine (ChromaDB / PGVector)] ──► Поиск клинических протоколов по симпотомам
        │
        └─► [Decider LLM Engine] ──► Формирование JSON-маршрута с помощью Structured Output
                │
                ▼
[JSON Data Output] ──► [Frontend Dashboard] (Визуализация карточки маршрутизации)

```

### 1.2 Поток данных (Data Flow)

1. **Ввод:** Пользователь загружает PDF-выписку или вводит текст эпикриза и результатов лабораторных исследований в веб-интерфейсе.

2. **Обработка:** Backend извлекает текст, отправляет его в RAG для поиска сопоставимых клинических протоколов маршрутизации.

3. **Принятие решения:** Decider LLM получает структурированный промпт (Текст выписки + Найденные протоколы) и генерирует валидный JSON по строго заданной Pydantic-схеме.

4. **Вывод:** Frontend отображает приоритет обращения, профиль отделения, список специалистов, критические риски и аргументацию решения с возможностью корректировки врачом (Human-in-the-loop).

## 3. Распределение задач по ролям (ТЗ для команды)

### 3.1 ML / LLM Engineer (Vova + Vlad)

* **Зона ответственности:** Интеллектуальное ядро системы, RAG, качество принятия решений LLM.

* **Технические задачи:**

  1. **Pydantic-схема:** Спроектировать Pydantic-класс для строгой валидации JSON-выхода (приоритет, отделение, врачи, риски, цитаты из выписки).

  2. **Prompt Engineering:** Составить системный промпт с Few-Shot примерами сложных медицинских кейсов для исключения галлюцинаций.

  3. **RAG-модуль:** Настроить векторное хранилище (ChromaDB) с 30-40 базовыми регламентами и протоколами маршрутизации.

  4. **Fine-Tuning (Bonus):** Дообучить малую модель (например, Llama 3 8B / Qwen 2.5 7B) с использованием LoRA/Unsloth на синтетических парах «Эпикриз → Маршрут» для демонстрации на питче.

* **Критерий готовности:** Python-модуль, принимающий текст эпикриза и возвращающий валидный JSON с решением.

### 3.2 Backend / Integration Engineer (Vova)

* **Зона ответственности:** Серверная логика, парсинг входящих документов, интеграция компонентов.

* **Технические задачи:**

  1. **FastAPI Сервис:** Реализовать REST API со следующими эндпоинтами:

     * `POST /api/v1/upload` — Загрузка и парсинг файлов (PDF/DOCX).

     * `POST /api/v1/route` — Вызов пайплайна маршрутизации (RAG + LLM).

     * `GET /api/v1/patients/{id}` — Получение сохраненного карточки пациента.

  2. **Парсинг документов:** Реализовать очистку и обработку текстов с помощью `pdfplumber` / `PyPDF2`.

  3. **Валидация и Фоллбэк:** Добавить обработку ошибок при невалидном ответе LLM и повторные попытки запроса (Retry Logic).

* **Критерий готовности:** Стабильно работающий API-сервис с Swagger-документацией (`/docs`), готовный к подключению фронтенда.

### 3.3 Frontend Engineer (Denis)

* **Зона ответственности:** Пользовательский интерфейс, представление данных для медицинского персонала.

* **Технические задачи:**

  1. **Auth (заглушка):** Экран входа по login + password; роли `client` / `admin` без реальной проверки на бэкенде (хардкод / mock).

  2. **Client-дашборд:**

     * Экран загрузки (Input Zone): Drag-and-drop форма загрузки документов, текстовое поле для ручного ввода/редактирования.

     * Дашборд маршрутизации (Output Zone): индикатор приоритета 🔴 *Экстренное* | 🟡 *Срочное* | 🟢 *Плановое*; карточка отделения, специалистов и анализов; блок обоснования (*Clinical Reasoning*).

  3. **Admin-дашборд:** Обзор маршрутов/решений, Human-in-the-loop — ручная корректировка предложенного маршрута и сохранение изменений.

* **Критерий готовности:** Интерактивный UI с client- и admin-дашбордами и stub-авторизацией, интегрированный с FastAPI бэкендом.
